Hand-check report: "skipping forward or backwards is super laggy and causes cutoffs for both audio and video. Audio can be off too and

Diagnosis (architect-opus, measured 2026-11-05, see docs/EVIDENCE.md "Wave 4 hand check"):
D1 Demo sources cannot seek: `-ss` before a lavfi input decodes from 0. First frame after -ss 30: mandelbrot 2,017 ms, cellauto 440,
   gradients 375, life 179, testsrc2 128; a real MP4 at -ss 30: 47 ms. (Task 4.7 fixes this with a cached file; not your job.)
D2 The clock is anchored at audio SPAWN time, but ffplay starts sound later (process start + SDL device open; Wave 0 measured ~0.35 s
   overhead), so after every play/seek/resume video runs ahead of audio ("audio off").
D3 Every pause/seek kills and respawns ffmpeg+ffplay, so sound has a gap of ~0.35 s+ ("takes a bit to start").
D4 After a seek the clock starts immediately while the new decoder has no frames yet; when frames arrive they are late and get dropped in a
   burst ("cutoffs").
D5 seekTo() and the 10 s timer call pipeline.invalidate(), which forces a FULL-screen redraw. Apple Terminal has no DEC 2026, so a big frame
   paints visibly top to bottom ("flashy"). The screen model is still correct after a seek or a mode/palette/depth change — the screen did
   not change — so those invalidations are unnecessary. restartDecoder() also CLEARs the screen (needed only when geometry changes).

Required design:
1. Long-lived audio output with a PCM pump (fixes D2, D3).
   - ONE ffplay per playback session, started once, fed raw PCM on stdin: `ffplay -hide_banner -loglevel error -nodisp -autoexit
     -fflags nobuffer -flags low_delay -probesize 32 -analyzeduration 0 -f s16le -ar 48000 -ch_layout stereo -volume V -i pipe:0`
     (verify these flags against the installed ffplay 9.0.2 with `ffplay -h demuxer=s16le` / a quick run; adjust and report).
   - A separate audio SOURCE ffmpeg decodes `-ss pos <input> -vn -ac 2 -ar 48000 -f s16le pipe:1` into our process.
   - Our process paces writes: keep the amount of PCM written ahead of the clock at LEAD_MS = 120 (constant; document it). Read from the
     source only as needed (pause its stdout = backpressure), write to ffplay stdin in chunks of ~20 ms.
   - Pause: stop writing (ffplay drains <= LEAD + device buffer, then plays silence), freeze the clock. Keep BOTH processes alive.
     Resume: continue writing from the same source. No respawn.
   - Seek: kill only the source ffmpeg and start a new one at the target; ffplay stays. Drop any PCM from the old source.
   - The audio clock is derived from PCM frames written: position = segmentStartSec + framesWrittenSinceSegment / 48000 - LEAD/1000 -
     outputLatency, where outputLatency starts at a constant (default 0.10 s, document) and --av-offset adds to it. Expose
     `positionSec()` and use it as the master clock when audio is on (REQ-SYNC-01). Without audio, the existing wall clock.
   - End of source: when the source ends and its PCM is written, report end; with --loop restart the source at 0.
   - Exit paths: killNow() kills both (killTreeSync). No orphan in any path.
2. Seek barrier (fixes D4): on seek, keep the last frame on screen, show the target time on the HUD, start the new video decoder and the
   new audio source, and do NOT advance the clock until (a) the first new video frame is decoded and (b) the first PCM chunk of the new
   source is available (or audio is off). Then start the clock at the target and present that frame. Drop no frames during the barrier.
   Bound the barrier at 3 s (then start anyway). Governor: ignore samples during the barrier and for 500 ms after it.
3. No unnecessary full redraws (fixes D5):
   - Remove invalidate() from seek, setMode, setPalette, setThreshold, setDepth: the screen model already describes the screen. (setDepth
     must keep the model valid across mapper changes: compare in RGB via toRgb so a cell shown in 24-bit is not considered equal to a 256
     index by accident — handle that correctly and test it.)
   - Replace the 10 s full invalidate with a rolling refresh: each frame, mark K rows of the model unknown (K = ceil(rows / 60), so the
     whole screen is refreshed about every 2 s at 30 fps) — encoder needs `invalidateRows(start, count)`; add it to src/renderer/encoder.ts
     ONLY if it is not there (allowed exception, list it).
   - CLEAR only when geometry changes (resize, cell cap). Seeks never CLEAR.
4. Keep everything else working: m/c/i, HUD, governor, resize, loop, PTY teardown, CI on all 3 OSes (Windows: no PTY tests; audio still
   uses ffplay; taskkill tree kill).
